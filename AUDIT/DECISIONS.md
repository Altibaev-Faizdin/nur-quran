# AUDIT/DECISIONS.md — Архитектурные и инженерные решения

В данном документе фиксируются все ключевые инженерные развилки и решения, принятые при приведении проекта Noor Al-Quran к production-качеству (согласно правилу 1: «Никаких вопросов владельцу. Выбери самое безопасное инженерное решение»).

---

## Решение 1: Уведомления о времени намаза (FUNC-01)
- **Контекст:** В проекте есть модель `PrayerNotification`, но на бэкенде отсутствует фоновый планировщик (Celery, cron, Redis Queue, Push-сервер WebPush / FCM).
- **Выбранное решение:** 
  1. В базу данных и API добавляется обязательный намаз `isha` в `PRAYER_CHOICES`, создаётся миграция и тесты.
  2. Пункт `sunrise` (восход солнца) сохраняется как опциональное напоминание с корректной пометкой в UI (*«Напоминание о восходе солнца (не фард-намаз)»*).
  3. На фронтенде реализуются локальные уведомления через браузерный `Notification API` с явным и честным предупреждением в интерфейсе: *«Уведомления работают локально при открытой или фоновой вкладке браузера»*.
  4. Модель и эндпоинты бэкенда сохраняются для будущей синхронизации настроек и серверной отправки.
- **Альтернативы:**
  - *Альтернатива А (Обещать push без сервера):* Нечестно по отношению к пользователям, приведёт к негативным отзывам.
  - *Альтернатива Б (Пометить "Скоро"):* Лишает пользователей уже работающего функционала оповещений об азане.

## Решение 2: Басмала в сурах Корана (FUNC-04)
- **Контекст:** В API `quran-uthmani` к первому аяту большинства сур префиксом приклеен текст Басмалы, а в интерфейсе `quran.html` есть отдельный декоративный заголовок `#rbis`. В суре 1 (Аль-Фатиха) Басмала официально является аятом 1, а в суре 9 (Ат-Тавба) Басмала отсутствует вовсе. В суре 27 (Ан-Намль, аят 30) Басмала встречается внутри текста.
- **Выбранное решение:**
  1. Сырой текст аятов в данных **никогда не изменяется** (правило 4 о священности текста).
  2. Преобразование выполняется **исключительно на уровне отображения (UI presentation)**:
     - Сура 1 (Аль-Фатиха): элемент `#rbis` скрывается (`display: none`), Басмала отображается как канонический Аят 1.
     - Сура 9 (Ат-Тавба): элемент `#rbis` скрывается (`display: none`).
     - Суры 2–8, 10–114: элемент `#rbis` отображается как декоративный заголовок суры. Если в тексте Аята 1 присутствует стандартный префикс Басмалы (`بِسْمِ ٱللَّهِ ٱلرَّحْمَـٰنِ ٱلرَّحِيمِ`), для отображения первой строки он нормализуется (скрывается дубль внутри текста аята 1, чтобы не было двух Басмал подряд: в шапке и в тексте), при этом в суре 27:30 внутренняя Басмала остаётся нетронутой.
- **Альтернативы:** Мутировать массив аятов в БД/кэше (отвергнуто, нарушает целостность данных).

## Решение 3: Хранение сессий и токенов (SEC-01, SEC-07)
- **Контекст:** Netlify проксирует `/api/*` на Render. Использование `HttpOnly` cookie требует сложной синхронизации CORS/CSRF между доменами Netlify и Render при прямой разработке.
- **Выбранное решение:**
  1. Полное удаление `demo-session-token` и любых фиктивных fallback-логинов. При ошибке сети выводится честное локализованное сообщение.
  2. Сокращение времени жизни `ACCESS_TOKEN_LIFETIME` до 15 минут, `REFRESH_TOKEN_LIFETIME` до 7 дней с включённой ротацией (`ROTATE_REFRESH_TOKENS = True`) и черным списком (`BLACKLIST_AFTER_ROTATION = True`).
  3. Токены хранятся через модуль `StorageManager` (префикс `nq_`) с валидацией срока жизни exp перед запросами и автоматическим перехватом 401 для бесшовного `refresh`.
  4. Строгая CSP и отсутствие XSS векторов для защиты `localStorage`.
  5. Для работы без авторизации закладки помечаются бейджем *«Локально»*.

## Решение 4: Драйвер PostgreSQL (BUILD-01)
- **Контекст:** `psycopg2-binary==2.9.9` падает при установке на Python 3.14/современных дистрибутивах без `libpq-dev`.
- **Выбранное решение:** Обновление до `psycopg2-binary>=2.9.10` и поддержка `psycopg[binary]>=3.2` в `requirements.txt` с проверкой совместимости с `dj-database-url` и Django.

## Решение 5: Расчёт времени намаза в высоких широтах (FUNC-02, FUNC-08)
- **Контекст:** В широтах выше 48°N летом солнце не опускается ниже 18 градусов, формула возвращает `null` (`--:--`).
- **Выбранное решение:**
  1. Исправление `fixHour` (mod 24) на `fixAngle` (mod 360) для углов склонения солнца.
  2. Внедрение правила `OneSeventh` (1/7 ночи) по умолчанию для высоких широт с возможностью выбора `NightMiddle` (середина ночи) или `AngleBased` (угловой).
  3. Замена жестко зашитого угла Фаджр/Иша на настраиваемые методы (`MWL`, `ISNA`, `Egypt`, `Makkah`, `Karachi`, `Tehran`, `Jafari`, `Gulf`).
  4. Добавление выбора мазхаба для Асра (`Standard` / `Hanafi`).
  5. Значение `--:--` устранено полностью.

## Решение 6: Единая страница чтецов (ARCH-02)
- **Контекст:** 10 страниц `reciter-*.html` содержат 2780 строк дублированного кода.
- **Выбранное решение:**
  1. Создаётся единая шаблонная страница `frontend/pages/reciter.html?id=<reciter_id>`.
  2. Реестр всех 10 чтецов централизован в `shared.js` (`window.RECITERS`).
  3. В `frontend/_redirects` и `netlify.toml` добавляются 301 редиректы со старых адресов (`/pages/reciter-alafasy.html` -> `/pages/reciter.html?id=mishary_alafasy` и т.д.).
  4. Старые 10 файлов заменяются либо удаляются после настройки редиректов и обновления ссылок во всём проекте.

## Решение 7: Офлайн-Коран (PERF-01)
- **Контекст:** Чтение Корана не работает в офлайне.
- **Выбранное решение:**
  1. Создаётся модуль `frontend/idb-store.js` на нативном IndexedDB (без внешних зависимостей) с версионированием схемы.
  2. Кэширование прочитанных сур (арабский + переводы).
  3. Стратегия: сначала IndexedDB -> параллельно сетевой запрос и обновление кэша.
  4. Кнопка «Скачать весь Коран для офлайна» с отображением прогресса и размера (~12-15 МБ).
